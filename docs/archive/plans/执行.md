### 1.2 冲突合并与 agent 自主权

- 本文的“用户约束”与“设计默认值”分开对待。默认值用于直接施工，不需要逐项再次请示；不能把它们描述成用户永久要求。

- agent 可自行决定文件命名、控件细节、纯函数拆分、复用或重写方式，以及不改变目标的默认参数调整。改变主入口、减少必达内容或扩大功能范围时，需说明证据、影响与取舍，不能静默执行。
- 不机械继承旧项目针对判题、学习档案、旧导航的要求；构建、签名、许可等仍适用的约束继续遵循。不修改指令文件来绕过权限或访问限制。
- 后续若用户要求“按执行.md完成首版”，默认连续推进 P0–P4；阶段验收是完成检查，不是每阶段等待批准的关卡。若只指定某阶段，按其范围交付。真实权限、签名或范围冲突阻塞时，完成其他不受阻塞的工作后一次说明缺项。

## 3. 最小工程与共享约定

### 3.1 工程职责

先用一个 `:app` 模块，包目录可按下表组织。名称不强制，职责要清楚；从可运行样例中提取必要共用代码，不先搭通用课程引擎。

| 职责 | 输入与输出 | 边界 |
| --- | --- | --- |
| 音乐事实与内容 | 调弦、弦品、音高、调性、指型、具体和弦指法与练法描述 | 尽量纯数据／纯计算，不引用界面、播放器或学习状态 |
| 指板与和弦绘制 | 已计算的音位、标签、音乐角色、临时高亮 → 绘制与点击位置 | 共用几何约定；不自己推导另一套音高，不自己推进播放 |
| 练习编排 | 内容选择、练法与参数 → 有限事件序列、循环长度、说明 | 音阶负责路线，和弦负责具体指法及弦序；共享事件格式，不强行共享全部业务流程 |
| 音频与播放状态 | 事件序列 → 声音、实际播放位置、当前事件和状态 | 一个播放控制入口，管理取消、循环与生命周期；高亮消费同一播放位置 |
| 页面 | 用户选择与临时状态 → 上述能力调用 | 不保存学习能力；轻量使用偏好可持久化 |

### 3.2 音乐与事件约定

1. 弦号固定为 1=最高音 E 弦、6=最低音 E 弦；标准调弦按 6→1 为 E2、A2、D3、G3、B3、E4，对应 MIDI 40、45、50、55、59、64。品位 0 为开放弦，闷弦单独表示，不能当作品位 0。
2. 音高用于发声，音名用于语境拼写，二者关联但不混为一个字符串。和弦指法保存每根弦的发声状态、有效品位及手指；若后续加入横按，同弦实际音高取有效的最高按弦品位。
3. 练习事件至少表达：起始位置、时值、发声内容、对应图示位置；休止有时值但没有音符起音。循环长度独立于最后一个事件的起始位置。根音、主音、当前发声和可见提示是可叠加的语义，不沿用“正确／错误答案”作为音乐角色。
4. 推荐采用每四分音符 12 tick，4/4 每小节 48 tick，八分音符 6 tick，与 002 时值素材兼容；也可采用精确有理拍长。音频端统一换算采样帧，并保留小数余量，不能逐事件独立取整造成累计漂移。
5. 和弦同响包含多个音；扫弦是多根有效弦短间隔依次起音；分解是按所选节奏逐弦起音。扫弦内部的短间隔可在音频端用采样帧表达，不强制量化成八分音符。不同演奏方式不得只换动画而播放同一种声音。
6. UI 依据实际播放位置更新，不能依据“已写入缓冲区的位置”提前亮起，也不能另开定时器自行推进音符。实现可以借用 002 的采样时钟，但最终只有一套时基。全静音时维持同一进度来源。
7. 音阶一轮为所选路线一遍，和弦一轮为完整所选序列。练习尾部不足整小节时，显式补休止到小节末，界面说明留拍后重来；不静默添音。循环、暂停定位和有限次数结束都采用编排后的同一长度。

### 3.3 播放状态与边界

| 操作或事件 | 统一行为 |
| --- | --- |
| 开始示范／跟练 | 清理旧播放；按当前设置生成序列。示范直接播放 1 遍；跟练先 1 小节预备拍再进入第 1 轮 |
| 暂停／后台 | 停止发声和推进，保留当前轮次及小节位置；回前台不自动响起 |
| 恢复 | 从暂停所在小节起点恢复，保持当前轮次；预备拍期间暂停则从预备小节起点恢复。明确显示从何处继续，不额外计数 |
| 重来 | 回到第 1 轮；跟练重新给预备拍，示范重新播放 |
| 切换内容、练法、速度、每和弦拍数或循环次数 | 立即暂停并作废旧序列；下次开始按新参数从头播放，跟练重新给预备拍 |
| 切换提示、音名／级数或声音开关 | 不重置时间轴。隐藏提示同时隐藏对应动态定位；开关只影响各自的可见或可听内容 |
| 自然结束／用户结束／离开练习 | 停止事件调度并清理声音；自然结束展示结束操作，离开页面不残留后台播放 |

## 4. 首个完整样例与内容基线

### 4.1 音阶样例 S1

选 C 大调 `mi 指型 · CAGED C 形`，使用下列一八度上行路线。它是明确的起步样例，不代表整型最低音一定是 C，也不要求其他练习都从这里开始。

| 次序 | 弦／品 | 实际音高 | C 大调级数 |
| --- | --- | --- | --- |
| 1 | 5 弦 3 品 | C3 | 1 |
| 2 | 4 弦 0 品 | D3 | 2 |
| 3 | 4 弦 2 品 | E3 | 3 |
| 4 | 4 弦 3 品 | F3 | 4 |
| 5 | 3 弦 0 品 | G3 | 5 |
| 6 | 3 弦 2 品 | A3 | 6 |
| 7 | 2 弦 0 品 | B3 | 7 |
| 8 | 2 弦 1 品 | C4 | 1（高八度） |

每音四分音符，共 2 小节；跟练预备 1 小节，默认 4 轮。必须能点音、切音名／级数、听完整示范、跟练及隐藏路线后再恢复对照。附加一次八分音符运行用于验证非整拍音符按事件发声，共 1 小节，不追加额外教学内容。

五型双名称固定为 mi→CAGED C、sol→A、la→G、si→E、re→D。原始数据以 001 的 `MajorScalePatterns.kt` 和 `docs/scale-patterns-v03.md` 为依据；只取音位、边界与名称，旧任务、判题和存档规则不继承。边缘音与重叠按该项目参考模板处理，不推广为全部教材的统一指法。

A 自然小调视角可沿用相同音位集合，但要以 A 为主音，示范按所选小调目标重新编排；关系提示明确区分音阶级数与相对主音的音程，不能只改标题。

### 4.2 双和弦样例 C1

首个转换采用 C→Am，每和弦 4 拍，一轮 2 小节。第一阶段每小节首拍整和弦起音，保持指法与拍点显示直到换和弦；不能把 4 拍保持误播为每拍重弹。规则下拨在 P3 另按每拍起音实现。

| 和弦 | 弦品（6→1） | 实际音名（6→1） | 参考手指（6→1） |
| --- | --- | --- | --- |
| C | X 3 2 0 1 0 | X C E G C E | — 3 2 — 1 — |
| Am | X 0 2 2 1 0 | X A E A C E | — — 2 3 1 — |

手指 1/2/3/4 分别为食指／中指／无名指／小指；“—”表示该弦不需要按弦手指，O/X 由弦品状态另行显示。以上是首版参考指法，不宣称只有这一种用指方式。

先完成 C、Am 的逐弦试听、整和弦试听、两和弦转换、提前提示、隐藏指法与恢复对照。分解样例采用 5→3→2→1 弦、每弦一拍；P3 为其他和弦配置可发声且清楚标示的弦序，不能盲目沿用含 X 弦的顺序。

### 4.3 P2、P3 内容完成口径

- P2 补齐五型和 R11 的练法；相同算法可复用于适用指型，不要求给每个组合手工编一套课。避免把纯随机点音当作模进或连接短句。三音模进、调内三度和连接各保留一个确定样例用于核对。
- P3 补齐八个开放和弦，并逐个核对弦品、用指、O/X、音名和发声；不把 001 当前仅有的四个形态当成完整来源。每个和弦先提供一种指法，不增设庞大的指法选择器。
- P0、P1 的样例直接发展为正式功能。不能另做一个演示程序，之后再把主体功能全部重写；也不能把仅两个样例的中间版本当作首版全量完成。

### 6.2 P1：优先消除播放与交互风险

### 7.1 最小验证集合

| 检查 | 覆盖的实际风险 | 通过方式与证据 |
| --- | --- | --- |
| 构建与核心 CI | 工程不能构建、关键数据／播放逻辑回归 | 构建通过；音乐事实、路线边界、时值与取消等必要测试通过。记录命令／CI 链接和结果，不为低影响样式增加镜像测试 |

| 音频与高亮 | 固定节拍冒充音符、写缓冲导致提前高亮、循环漂移、暂停／退出残音 | 事件与音频输出验证结合短设备检查；至少覆盖 S1 两种细分、C1、一个休止、P3 下拨和分解。无真实设备结果时明确标注，不能从单元测试推断已验证听感 |

| 交互与布局 | 看不清、找不到入口、隐藏提示泄露答案、主要按钮不可达 | 检查一个代表性手机竖屏与横屏；两入口各走一个完整流程。涉及绘图或布局变更才补对应检查 |

相同未改动能力沿用已有有效证据；最终安装冒烟只确认打包与集成，没有发现新风险时不重跑全部人工流程。测试以验证音乐与运行规则为目标，不以覆盖率、测试数量或长时间稳定运行作为新增目标。
