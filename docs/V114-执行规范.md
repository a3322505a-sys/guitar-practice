## 二、审计确认的事实（不要误删）

基于 v113 Git tree：747 个 blob；54 个 `src/main/java` Kotlin 文件、18 个 `src/debug/java` 历史 Kotlin 文件、24 个 JVM 测试文件。`docs/` 有 393 个文件约 89.7 MB，其中 `docs/screenshots/` 为 288 张约 88.1 MB；`src/debug/assets/` 15 个文件约 2.1 MB。`src/p0/` 有 9 个历史探针/资源文件。统计针对 v113 HEAD，不代表 APK 大小。

- **实际故障链**：`PlaybackMix.load()` 在缺少新版音量 key 时将旧 `click=false` 解释成 `metronome=0`；`AlphaPlayback.countInGain=AlphaTone.CLICK * mix.metronome * 0.7`。alphaTab 1.8.4 在 `countInVolume <= 0` 时直接跳过内置预备拍。若这个状态保留在旧偏好中，重新点亮节拍按钮也无法恢复。需添加迁移/复现测试；真机实测前不能声称它是唯一故障源。
- `AlphaPlayback.startVisits(..., forceCountIn: Boolean=false)` 的参数当前无读取点（v111 就已存在）；可清理**参数及调用点**，但不要误删聚焦选段的入拍语义。
- `Phrases.all`、`Phrases.catalogue` 当前为空，`Phrases.named()` 的兜底会返回 `NativeIntro`。`SongRepository.named()` 实际调用此兜底。应评估缺失/失效曲目时改用明确错误/空状态，避免以不相关的 C 大调练习代替用户曲目；不要只删 `NativeIntro.kt` 导致引用断裂。
- **`LegacySequenceAdapter.kt` 仍是活动依赖**：`Sequence.performance` 在无 `runtimePlan` 时调用它，而 `AlphaPlayback.audition()` 构造临时 Sequence -> `AlphaScoreAdapter.audition()` -> `fromSequence()`，因此当前试听链仍可能经过该适配器。未完成等价替换及回归测试前禁止删除。
- `ui/PracticeSettings.kt` 中的 `ImmersiveOverlayWindow` 被 `SongLibrary.kt` 调用；`ThemePreviewCard`/`ThemePicker` 属于主题管理；`Diagrams.kt` 的 StageFretboard 属于唯一指板，不能只按文件大小或名称删除。
- `callbackEpoch`、`generation`、主线程回调防过期、`stopDisplayCursor`、曲包读取/Schema/StrictJson/ScoreValidation/PracticeCompiler 负责并发正确性与坏数据隔离，属于有效保护，不是应删的“防御性代码”。

## 三、必须先做：原生预备拍恢复（P0）

1. 精确对比 v111（`codex/v4-playback-controls`）、v112 和 v113 的 `AlphaPlayback.kt`，只把预备拍相关控制收敛为**一种** AlphaTab 原生调用方式。清理重复 `applyMix`/`countInVolume` 赋值、无用标志位、人工 0.7 衰减；不要把整个文件重置到 v111。
2. 确立一个唯一的 `applyMix` 音量出口：页面【节拍】只控制**正式节拍器**，`pre=true` 的内置预备拍请求不依赖旧 `click` 布尔值；正常有声时 `countInVolume` 必须大于 0。若产品保留明确的独立静音偏好，该语义与 UI 必须一致，并为其写用例。不能再让“关闭节拍按钮”变成“永久关闭预备拍”。
3. `PlaybackMix.load()` 不得再用旧 `click` 开关反推独立音量。迁移测试覆盖：无新 key + 旧 click=false；有非零音量；有明确零音量；冷启动与重新打开开关。不要在未验证情况下删除已有合法混音偏好。
4. 验证 `pre`、`countInVolume`、`api.isReadyForPlayback`、`play()` 状态及原生节拍事件，记录必要的**一次性启动诊断日志**，消除噪声日志。视觉红黄绿灯只能监听原生事件，不能再反向设置声音状态。
5. `resume()` 不重复完整预备拍；`restart()` 重新按完整预备拍开始。首拍强音仍不用注入方案。保持选段/弱起/不同拍号行为由原生引擎负责，异常用日志和测试识别，不新增人工填拍。
6. 回归：4/4、3/4、6/8，弱起与首小节休止符，第一次播放、暂停/继续、停止/再播、重来、循环、节拍开关开/关、旧 prefs 迁移；检查绿灯与音乐入口大致对齐。**音频有声、拍数与第一拍正常**才算完成。
