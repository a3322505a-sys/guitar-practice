# v91：和弦来源、TAB 与预备拍修复

基线为最新 `main` 的 `2bec43c`（PR #12 / v90），使用现有 `work/alphatab-p0` 工作目录和 `codex/v91-chords-tab-cursor` 分支。主目录未提交的 v82 排版保留。包名、长期签名、用户资料目录和 `.gpractice` 协议保持，版本为 v91 / 4.1.0-local43-alphatab。

## P1：所选和弦的来源事实

修复前，以 Repository 实际加载的《斜阳》和弦运行两条原有调用链，均复现 `NoSuchElementException`：

- `Sequence.chordAt → Chords.named`。
- `Sequence.performance → LegacySequenceAdapter.compile → Chords.named`。

这是源码路径复现的堆栈，未取得用户原设备的历史崩溃日志；修复前证据保留在本地 `work/v91-p1-before.xml`。曲包和弦选择后只保留名称，后续误查基础和弦表，是已证实的共用缺陷。

生成练习时，现有 Section 现在携带所选 Chord 与唯一身份，卡片、指板、逐弦练习和原生适配使用同一份事实。编译的 voicing/harmony 以身份关联，保留弦品、手指、X/O、教学信息、调弦与 Capo；点音及整和弦请求显式传入来源调弦/Capo。未知旧引用或确实缺失的指法显示不可用，不替换为同名基础指法。没有新增注册表、歌曲分支或和弦推断。

现有数据共有 32 张教学卡：基础 12、《嘘月》4、《斜阳》16；莫扎特和 YourTrip 曲包没有教学卡。现有卡片均为标准调弦，Capo 为 0 或 3；其他调弦的贯通仅用明确标注的测试夹具验证。同名不同指法检查在测试中保留两份已审核指法、仅统一显示名称，不向生产曲包添加虚构事实。

## P2：仅 TAB，保留真实元数据

工作台适配谱与原生 GP 共用 `AlphaNotation.prepare`，使用 alphaTab 已有 Staff 可见性开关隐藏五线谱，保留 TAB 的节奏连梁、时值、休止与奏法。Capo、调弦仍属于各原始 Staff，SDK 将必要的共享效果带显示在 TAB 上。

审核素材适配时只产生初始和真实变化的 tempo；GP 原始速度事件保留数值、位置与列表，仅清理同值标记的显示。小节中途变化继续使用精确 ratioPosition。固定跟练速度仅在 SDK 同步生成 MIDI 时临时应用，并在 finally 中恢复源谱列表，旋转或切轨后仍显示原谱速度。

## P3：预备拍起点与粉色光条

设置 playbackRange 后显式 seek 到选段实际经过的起始 tick，按引擎的 beat bounds 滚动定位。预备拍期间冻结在该起始拍；开始收到正式播放位置后再跟随。暂停继续关闭 SDK 会在每次 play 时重播的预备拍，继续使用播放器实际回报的暂停 tick。

SDK 1.8.4 的暂停回调使用 `getBeatStart`，该查询返回谱面小节首次经过的 tick；原生 GP 的后续重复经过因此可能跳到前一次。暂停前保存引擎实际 tick，并在 SDK 暂停回调及续播前恢复；过滤中间错误 seek 的界面投影。此处仍由同一个引擎定位，没有重新计算或运行软件播放时钟。

通过 SDK 的 `customCursorHandler` 将原 1 单位细线呈现为 12 单位半透明粉色光条；位置、每拍动画时长、循环和跨行边界仍来自同一引擎，没有第二个时钟。每次放置都取消旧动画，避免旧行或旧轮动画继续推进。

## 验证与交付

本地相关 JVM 检查共覆盖 46 项用例：首轮 43 项通过，另 3 项的旧 MIDI 导出校验不支持 MIDI2 滑音事件；保留奏法并改为比较所有事件字段后，该组 5 项重新通过。P1 的 8 项包含全部 32 卡前后滑动、点音/整和弦请求、开始练习和缺损邻卡返回；这些 UI 检查使用记录播放器，不表示已经听到原生输出。Python 素材 4 项、曲包 13 项通过。

P2 核对 GP 原生解析、每轨调弦/Capo 与清理前后 MIDI 事件一致，小节中途变速的 .375/.625 比例和对应 MIDI tick 正确；600/1200 宽度的 SVG 检查确认单 TAB、节奏、Capo/速度数量和 P.M. 保留。主机 SVG 字体度量与目标设备不同，不作为手机/平板视觉布局验收。P3 检查选段起点冻结、旧回调过滤、两轮及跨行光标坐标/引擎动画参数。
