# 曲包导入、曲包库与连续练习：整合实施方案

> 基线：2026-11-02，codex/song-package-v2，App 1.4.5 / versionCode 115。本文是待实施方案，不代表功能已经上线。

## 目标与边界

用户下载曲包后能直接导入；曲包很多时能迅速找到；练完一段可以继续下一段或换曲包。仅优化入口、列表、选择状态；继续复用 SongRepository、SongReader、PhraseSettingsStore、现有 AlphaTab 播放器和练琴舞台。底部只保留【BPM / 播放 / 循环 / 节拍】，不增加模式开关或第二播放器。兼容 minSdk 26（Android 8.0）。

## P0：外部打开与分享导入

1. 在 AndroidManifest 为 MainActivity 注册可接受曲包的 ACTION_VIEW、ACTION_SEND；处理首次启动和 onNewIntent，读取 content:// URI，检查读权限，不索取全盘存储权限。避免 * / * 的宽泛文件关联；必要时在“分享”入口提供更广 MIME 兼容，进入后由解析器判定内容。
2. 将系统 OpenDocument 的 URI 与外部分享/打开 URI 合流到同一导入动作：ContentResolver.openInputStream → SongRepository.prepare → 显示名称/练习数/同包已有版本 → 确认 → SongRepository.commit → 刷新曲库。用户取消不改变曲库。复用现有事务，不新写解析器。
3. 按内容识别而非只信扩展名。支持 .gpractice，以及实际容器就是曲包的 .gpractice.zip；绝不解压 ZIP 中的二层 ZIP 来假装正确曲包。任意普通 ZIP 不导入。
4. 导入成功后回到曲包库并定位新曲包，提供“开始练习”。重复导入同 packageId 使用现有 revision/digest 更新或复用规则，禁止靠标题强行合并。
5. 手动“选择曲包”保留为备用。暂不做全盘扫描、后台服务、系统权限弹窗或直接接 Google Drive API。

## P0：练琴舞台连续切换

1. 谱面上方显示【上一段 ‹ | 当前曲包 · 段名 · 序号 ▾ | 下一段 ›】。点击标题弹出当前曲包的段落列表；序号按曲包自身的 order 排列，跳过隐藏/停用项。
2. 切换段落先停止当前播放、失效化旧光标，再走既有 phraseChange / resolve / prepareSequence 流程；不重建 AlphaTabView、不换播放内核。
3. 播放自然结束显示轻量操作【再练一次 / 下一段 / 换曲包】。下一段仅限当前曲包；最后一段显示“已到最后一段”，不偷偷跳到另一曲包；换曲包打开最近/收藏的底部选择层。
4. 保留 BPM、循环、节拍的当前意图：同一首歌连续切段不应无提示恢复随机默认值。已单独保存的段落参数按现有 PhraseSettingsStore 规则优先，不另外建立第二份速度数据库。
5. 上一段/下一段只在当前曲包可播放段落间导航；教学自由选择，既不强制按顺序，也不增加解锁/判题逻辑。

## P1：紧凑曲包库与快捷继续

1. 曲包库首屏：搜索入口、最近一次【继续练习】、分类切换【全部/最近/收藏/教学/歌曲】，下面用单行紧凑列表替代大面积重复卡片。手机和平板沿用现有主题系统。
2. 默认最近使用优先；支持标题/作者/段落名称的本地不区分大小写搜索，无需网络和数据库。分类沿用教学元数据，不另建全量内容副本。
3. 使用 SharedPreferences 保存最近曲包与段落 ID、收藏 ID（例如最近最多 20 条）；保留现有 selected / PhraseSettingsStore 语义，遇到已停用或不存在的 ID 自然回退到曲库，不做复杂迁移框架。
4. 以 packageId 为曲包身份，同一包只显示当前启用修订；历史修订仍在管理界面恢复。不同 packageId 即使同名也不自动合并，可在副标题显示作者或来源区分。
5. “换曲包”浮层仅展示最近与收藏，提供“查看全部”；曲库仍保留全部曲包的完整选择路径。

## P2（可选）：指定文件夹发现

只在 P0 / P1 仍不够方便时增加。首次让用户通过 ACTION_OPEN_DOCUMENT_TREE 授权一个非受限专用目录（如 Documents/吉他曲包），持久化该目录 URI；进入曲包管理时或点击“扫描新曲包”才枚举该目录中的 .gpractice 和 .gpractice.zip，并列出尚未导入候选供确认。Android 11+ 不依赖 Download 根目录授权；不请求 MANAGE_EXTERNAL_STORAGE、不后台监听、不递归全盘搜索。下载目录中的文件仍可通过“打开/分享”直达。

## 重复曲包与异常处理

- 截图里同名曲包重复不等于同一 packageId；先检查当前 UI 的分组、重复 composable/列表渲染、修订历史和实际 identity。用包 ID 解决真正重复显示；不改曲包 ID、不按标题删包。
- 导入错误只展示失败文件与简短原因，不阻断其他曲包使用。处理 URI 丢失、取消、已导入、冲突以及不是真曲包的 ZIP 即可。

## 最小实施范围与验收

可能涉及：app/src/main/AndroidManifest.xml、MainActivity.kt、ui/SongLibrary.kt、ui/PracticeApp.kt、practice/PhraseSettings.kt（或既有偏好封装）；SongReader / SongRepository 保持复用，只有证实必要的兼容小修才改。按个人项目轻量原则直接在现有文件修改，不增第三方库，不为边界检查造新框架。

只验收核心主流程：(1) 系统下载文件→打开/分享→预览→导入；(2) .gpractice.zip 单层容器可以不改名导入，二层 ZIP 被拒绝；(3) 重复修订只出现一个启用条目；(4) 搜索/收藏/最近/恢复；(5) 上下段连续切换、结束后下一段和换曲包，播放/光标无串线；(6) Android 8.0+ 的现有兼容性不回退。CI 核心检查通过后可按原交付流程出 APK；真机未验收要明确标注。
